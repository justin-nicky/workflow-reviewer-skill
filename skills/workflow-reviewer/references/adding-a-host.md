# Adding a host: the adapter flow

A host with no built-in mapping (or a new transcript format of a known host) is added in this order. Every step is read-only until `--save-adapter`, and nothing the probe prints contains content.

1. **Probe.** `transcript_metrics.py --probe PATH` on a transcript file (jsonl or json), a session folder (file kinds, sizes and counts only, three levels deep) or a sqlite database (named tables only, read-only, never virtual or search tables). It prints JSON paths with their types and how often each appears, the values of `type`, `role`, `kind`, `status`, `say`, `ask`, `event` and `subtype` fields when they are short identifiers that repeat, timestamp shapes (ISO, epoch seconds or milliseconds) and array lengths. It never prints text, paths inside values, ids or anything else. Caps: 200 paths, 50 values per group, 5,000 records; a file over 200 MB is exit 4.
2. **Draft a mapping** (every key it may use, with one line each: [mapping-keys.md](mapping-keys.md)) in the shape of the files in `scripts/mappings/`: `schema_version = 1`, a `[container]` kind (`jsonl`, `sqlite` or `json_document`, see hosts.md), `[capabilities]`, `[fields]`, `[[records]]` rules, and `[[skill_folders]]` where the host has them. Keys are declarative data only; an unknown key is refused. Declare `[[checks]]` (second counts) for the core metrics wherever the host makes it possible, and keep only those that hold on real sessions. A metric with no second count stays `one_way`, which is normal. List harmless metadata record types under `ignore`.
3. **`--save-adapter NAME`.** Pipe the drafted mapping on stdin (`... --save-adapter NAME < draft.toml`, with the usual selection arguments for the session to check it against). The script validates it (schema_version, declarative keys, identifier and regular-expression rules), runs it against that session and writes the file only if no core metric is broken. The file goes to `$XDG_CONFIG_HOME/workflow-reviewer/hosts/NAME.toml` (default `~/.config/workflow-reviewer/hosts/`; `%APPDATA%\workflow-reviewer\hosts\` on Windows), mode 0600 in a 0700 folder. It never overwrites unless `--replace` is given, adds `made_by = "workflow-reviewer adapter flow"` and `made_from_version`, and prints the path. Cannot be combined with `--mapping` or `--report` (both read stdin).
4. **Health ok.** Re-run with `--host NAME --health-all`. The adapter is labelled `unproven` in the output and in reports until it is merged as a built-in. Core metrics (turns, tool_calls, tokens where recorded) must be `ok` or `one_way` and the presence checks must pass: the health table breaks tokens ("no token usage found") and tool_calls ("results without calls") when the replies, usage or calls and results cannot be reached, however high coverage is.
5. **Fixtures.** `--make-replica` writes a synthetic golden replica of the session (placeholder text, regenerated ids, no real content; declare what it may keep under `[replica]` in the mapping: `keep_paths`, `id_paths`, `command_paths`, `keep_patterns`). Then add the mutation rows for the host in `tests/test_health_mutations.py`: renaming the turn marker, dropping the result record type, renaming a usage field, adding an unknown record type and duplicating an assistant record should each turn the right row to warn or broken and leave unrelated core rows ok. Say which cells the host cannot show.
6. **Pull request.** `--pr-bundle` prints the paths, the expected numbers and the commands (it runs nothing). Add the mapping to `scripts/mappings/` with `tested_versions` taken from the versions actually seen, an environment marker under `detect` only if you verified it (names only), and the fixtures. Then it is `verified`.

A user adapter for a host that already has a built-in mapping adds a variant, chosen by shape like the built-in ones. It never replaces a built-in variant, and on a tie the built-in wins.

The contributor guide for the whole flow, run outside a review, is [adapter-flow.md](adapter-flow.md). A user variant for a built-in host may add mappings but never remove or loosen that host's checks.
